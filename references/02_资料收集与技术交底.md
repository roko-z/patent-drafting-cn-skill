# 02 技术资料收集、技术交底与事实核对

## 从零启动的六类资料

1. 基本信息：初拟名称、领域、应用场景、发明人贡献、申请人、保密等级、论文/展示/预印本公开状态、拟申请地。
2. 技术现状：已有产品/论文/专利的技术原理，使用时遇到的可描述的技术困难；最好附最接近现有技术原始来源。
3. 新技术方案：系统总体框图、组成、必要技术特征、部件连接/方法步骤、变量、控制条件、实施流程。
4. 实际实现：制造或部署条件、工艺顺序、运行参数、设备/材料型号（若有）、替代实现及对应效果；负面实验也保留。
5. 效果证据：原始数据、同条件对比例、重复次数、测试误差、测量单位、测试方法、图源和来源说明。
6. 图示资产：CAD/矢量图/流程图/电路图、照片与真实关系说明、图号或部件名称台账。

## 缺失项三级处理

- **P0 停止点**：发明权属或公开时间未核实；存在伪造或矛盾重大事实；核心技术原理不明；当前文档可能包含不具备使用授权的他人保密内容。此时只能提供问题与草稿，不能称可直接申请。
- **P1 影响独立权利要求**：主构件连接关系/算法输入输出/制备关键条件缺失；某特征没有可实施方案；对比文件未完成核心差异核对。
- **P2 局部完善**：可选材料、特定数值、辅助测试图、非必要美化排版尚未统一。

## 技术交底书建议结构（工作底稿）

1. 基本著录及公开状况。
2. 背景技术与需要解决的问题（尽量引用具体公开技术）。
3. 核心技术构思（用一句话说明技术上发生了什么变化）。
4. 独立实施的最小系统/方法（不能只写目标）。
5. 各关键构件/步骤、连接关系及工作机理。
6. 优选参数、可替代方案、变化边界。
7. 研发及试验方法，能重复执行的完整步骤。
8. 数据来源、对比例、预期效果与已测效果区分。
9. 拟申请主题、主要创新点和备用创新点。
10. 附图清单、图号/部件标记字典。
11. 现有技术检索线索。
12. 论文/报告首次公开与权属资料。
13. 待补充问题与发明人签字确认项。

## 论文转专利专门处理

论文的“研究结论”不等于可直接写入专利的“技术方案”。逐段映射：

| 论文内容类型 | 可被转化的专利材料 | 容易缺少的关键证据 |
|---|---|---|
| 背景、引言 | 背景技术、待解决技术问题 | 最接近现有技术完整文本 |
| Methods | 具体实施方式、工艺步骤 | 每一步的参数、范围、可复现条件 |
| 装置示意 | 附图和结构说明 | 构件对应、连接关系、实现方式 |
| 实验曲线 | 有益效果、实施例 | 测试条件、误差、原始数据 |
| Results | 已测技术效果、实施例 | 真实对照、跨条件可重复性 |
| Discussion | 作用机制解释和优选形式 | 推测与实证的界限 |
| Conclusion | 摘要思路来源 | 不可直接改写成空泛的专利效果 |

**明确标注**：`[原文直接支持]`、`[专业推断]`、`[发明人待确认]`。机翻优先核对关键英文术语与原文、图注及数据。

## 发明人确认提问模式

提问应具体、可被技术人员回答，而非“请提供更多细节”。例如：

- “请确认模块 A 与模块 B 的直接信号连接是单向、双向，还是通过中间电路实现？如有，提供电路图。”
- “参数范围 X～Y 是实际测过的范围还是拟申请的保护范围？请分别列出已测点。”
- “曲线 C 的采样频率、负载、环境条件、误差与重复次数分别是什么？”
- “与现有方案 D1 相比，哪一组特征形成实际技术差异？”

## 事实台账

每一事实编号 `F001`，记录原始文字/图片所在页、确认级别、待用章节、关联权利要求、冲突记录。相同名称的符号、单位和部件号必须全局唯一；命名冲突需回发明人确认。
